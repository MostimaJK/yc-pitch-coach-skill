# YC Pitch Coach Skill · 專案敘事與路演教練

**先理解專案，再把價值講清楚。**

這是一個以繁體中文介紹、支援中文對話的 Codex Skill，參考 Y Combinator（YC）的公開路演建議，透過逐步訪談，協助你釐清專案、回答關鍵商業問題，形成有證據的專案故事與路演內容。

不必事先準備好完整商業計畫。即使你只有一些程式、零散想法，或不知道誰會付錢，也可以先從具體事實開始。

> 本專案獨立編寫，並非 YC 官方產品，也未獲 YC 背書。技能指令目前以簡體中文撰寫；可依使用者偏好以繁體中文、簡體中文或其他語言對話。

## 這個 Skill 究竟在回答什麼問題？

它要協助你回答的核心問題是：

> **你正在為誰解決什麼問題？你已經證明了什麼？為什麼這件事值得繼續投入，以及為什麼由你們來做？**

再依聽眾調整重點：

| 聽眾 | 他們需要理解的問題 |
|---|---|
| 比賽評審 | 你完成了什麼？難點與差異在哪裡？效果如何驗證？ |
| 潛在客戶 | 它能改善我的哪段工作？如何試用、導入與驗收？ |
| 投資人 | 誰會付費？機會有多大？目前證據與成長路徑是什麼？ |
| 招募／合作對象 | 團隊做過什麼？各自貢獻與下一步需要什麼？ |
| 創辦團隊自己 | 哪些已經清楚，哪些只是相信，下一步先驗證什麼？ |

這個 Skill 會先幫助你整理思考，再處理文案。尚未驗證的商業假設，不會被寫成既有成果。

## YC 是什麼？這裡採用了哪些方法？

Y Combinator 是創業加速器。本專案主要參考其合夥人分享的三組方法：

- **Michael Seibel 的七問**：檢查你是否說清楚專案與商業機會。
- **Geoff Ralston 的故事主線**：挑選少量值得記住的觀點，反覆練習與刪減。
- **Kevin Hale 的簡報原則**：讓投影片易讀、簡單，核心意思明顯。

它們不是一套固定頁數、固定順序或保證成功的公式。以下七問說明是對公開方法的簡要整理；後面的訪談、例子與工作流程則是本專案的實務改編。

## YC 的七個問題

| 問題 | 核心要回答什麼 |
|---|---|
| **1. 你們做什麼？** | 產品的使用者、用途與結果。 |
| **2. 市場有多大？** | 哪些客戶可能需要它，機會範圍有多大。 |
| **3. 目前有什麼進展？** | 在投入的時間內，實際完成了哪些事情。 |
| **4. 有什麼獨特洞察？** | 你對問題有哪些具體、不同的理解。 |
| **5. 商業模式是什麼？** | 誰付錢，以及如何取得收入。 |
| **6. 團隊是誰？** | 哪些人共同執行，相關能力與投入如何。 |
| **7. 希望對方做什麼？** | 這次溝通希望促成的明確行動。 |

原始框架：[Michael Seibel — How to Pitch Your Company](https://www.ycombinator.com/blog/how-to-pitch-your-company/)。

以下是本 Skill 如何帶你回答這些問題，並非要求一次填完的問卷。

### 1. 你們做什麼？——從一次真實使用開始

你不需要先解釋架構。可以先說明：

- 誰打開產品？
- 他當時手上有什麼資料或任務？
- 產品幫他完成什麼？
- 結束後拿到了什麼結果？

**本專案的引導句式：**

> 我們幫助【具體使用者】，在【場景】中，透過【關鍵動作】完成【結果】。

如果你只說「這是一個 AI 平台」，Skill 會協助你找出具體任務；目前沒有使用者時，就先提出候選對象與驗證方式。

### 2. 市場有多大？——先界定誰真的可能成為客戶

這裡會先釐清目標地區、客戶類型、需求與付費方式，再估算機會。

例如可以討論「某一類企業團隊，每年可能為這項服務支付多少」，但其中的客戶數量與價格都需要來源或假設標記。市場機會、實際營收和利潤會分開表述。

若你完全不知道，Skill 可以先幫你選定一個初始客群，再安排調查，而不急著填上一個龐大的數字。

### 3. 目前有什麼進展？——區分做出來與有人需要

本 Skill 會分開整理：

- 已有程式與功能。
- 哪些流程實際運行過。
- 測試樣本、環境與結果。
- 真實使用、重複使用、試點與付費。

尚未上線也能介紹有價值的開發進展；但程式存在不代表客戶需求已成立，合成資料測試也不代表真實場景表現。

### 4. 有什麼獨特洞察？——找出影響產品取捨的發現

Skill 會從你的經歷與觀察出發：

> 最近一次完成這項工作，時間到底花在哪裡？哪個發現改變了你的方案？

**示意假設：**某類文件工作的主要負擔，可能在查證而非撰寫。因此，產品優先提供原文定位與逐項核對。

這種說法可以指導開發與測試，但在沒有訪談或觀察證據時，仍然只是待驗證假設。模型名稱、學歷與漂亮介面本身，不會被當成洞察。

### 5. 商業模式是什麼？——釐清一次交易如何成立

Skill 會協助區分使用者、購買決策者與付費者，並討論：

- 買的是帳號、使用量、交付成果，還是服務？
- 為什麼願意在現有做法之外花錢？
- 交付成本與後續維護由誰承擔？
- 哪種方式值得先做小規模測試？

訂閱、按量計費、付費試點都可以作為候選，而不是提前替你決定答案。免費、開源或公益專案，則可以討論持續營運的資源來源。

### 6. 團隊是誰？——把背景連到具體執行

Skill 會從分工與相關成果整理團隊介紹：

> 誰負責哪段工作？過去完成過什麼，能幫助處理眼前難點？還缺少哪些能力？

不會只堆砌學校與公司名稱，也不會自行推定全職狀態、股權安排或雇主背書。

### 7. 希望對方做什麼？——讓下一步可以採取行動

不同場景可以有不同請求：

- 比賽或產業合作：提供樣本、安排業務評審、討論試點。
- 客戶交流：約定任務、雙方投入與驗收條件。
- 融資：確實有融資意圖時，再討論資金用途與里程碑。

Skill 會幫你把請求說清楚，不會自動替你聯絡對方或承諾交易條件。

## 我不知道答案時，它會怎麼做？

例如，你說：「程式做出來了，但不知道誰會付錢。」

它會依序：

1. 整理你已經具備的能力與證據。
2. 提出少量候選客群，說明各自可能受益的原因。
3. 改問容易回答的問題，例如「你目前能接觸哪一類人？他們現在怎麼做？」
4. 把仍未知的部分記為假設，提出低成本驗證方法。
5. 繼續完成不依賴該未知事實的介紹。

你不必一次知道所有答案。對話的目的，就是逐步釐清。

## 核心工作流程

**理解專案 → 整理事實與證據 → 輔導七問 → 提煉故事 → 按場景交付 → 排練與回饋。**

過程中區分：有證據的事實、使用者陳述、推斷、假設、未知與未來目標。每輪通常圍繞一個主題，提出 1～3 個具體問題；已有答案就不重複追問。

## 可以產出什麼？

依需求選擇，不會每次全部生成：

- 一句話定位、兩句話專案介紹。
- 七問答案與證據缺口。
- 故事主線、指定時長講稿、逐頁內容。
- 產品演示腳本與備用方案。
- 逐題模擬答辯及回饋。
- 下一輪驗證計畫、可複製的專案狀態摘要。

本 Skill 主要負責理解、內容與輔導。實際產生簡報檔案，需要環境中可用的簡報製作能力；本倉庫不包含自動生成 PPT 的程式。

## 安裝與使用

GitHub 倉庫名稱是 **`yc-pitch-coach-skill`**；技能識別名稱及呼叫方式維持 **`yc-pitch-coach`**。

下載或複製本倉庫後，將其作為完整的 `yc-pitch-coach` 資料夾，放入 Codex 個人 skills 目錄（通常為 `~/.codex/skills/`，有自訂設定時依實際設定）。保留 `SKILL.md`、`agents/`、`references/` 的相對結構。已有同名技能時，先比較再合併，避免覆蓋本機修改。

在專案對話中使用：

```text
請使用 $yc-pitch-coach，先閱讀目前專案，幫我理解使用者、價值與差異。
我有些商業問題不知道怎麼回答，請逐步引導，並使用繁體中文。
先不要急著製作簡報。
```

或限定任務：

```text
請使用 $yc-pitch-coach，準備這個專案的 5 分鐘比賽路演主線。
先區分事實與假設，再安排演示與證據。
```
